> **작성일:** 2026-09-21  
> **작성자:** James (Jewoo Yeon)  
> **목적:** AI 도구(Devin·Claude·Cursor 등)로 개발하는 자체 프로젝트를 체계적으로 관리

---

## 1. 시스템 개요

자체 개발 프로젝트가 늘어날수록 **"어디까지 만들었고, 어떻게 실행하며, 다음에 무엇을 해야 하는가"**를 즉시 확인할 수 있어야 한다. 이 시스템은 프로젝트 목록 → 프로젝트 상세 → 작업·프롬프트·문서·실행 정보 구조로 개발 과정 전체를 기록하고 추적한다.

## 2. 핵심 관리 항목

### 2.1 개발 내용·일정

| 필드 | 설명 | 예시 |
|------|------|------|
| 프로젝트 목적 | 한 줄 요약 | "페인트 제조 MES 엑셀 → DB 이관" |
| 주요 기능 | 핵심 기능 목록 | 엑셀 분석, ERD 생성, 데이터 이관 |
| 시작일 / 목표일 | 일정 범위 | 2026-09-01 ~ 2026-10-15 |
| 우선순위 | 상 / 중 / 하 | 상 |
| 진행 상태 | 기획 → 개발 → 테스트 → 배포 → 완료 → 중단 | 개발 |
| 다음 할 일 | 바로 착수할 작업 | "로그인 API 연동" |

### 2.2 프롬프트·히스토리

프롬프트는 **단독 보관이 아닌 작업(Task)에 연결**하여 관리한다.

```
작업 예시: "로그인 기능 개발"
  ├─ 요구사항 정의
  ├─ 입력 프롬프트 (원문)
  ├─ 사용 도구: Devin / Claude / Cursor
  ├─ 사용 일시: 2026-09-20 14:30
  ├─ 결과 요약
  ├─ 수정 요청 내역
  └─ 최종 커밋: abc1234
```

| 필드 | 설명 |
|------|------|
| 사용 도구 | Devin, Claude, Cursor 등 |
| 프롬프트 원문 | 입력한 프롬프트 전문 |
| 사용 일시 | 타임스탬프 |
| 결과 요약 | 생성된 코드·문서 요약 |
| 관련 작업 | 연결된 작업(Task) ID |
| 관련 커밋 | Git 커밋 해시·PR 번호 |

### 2.3 Markdown 문서

| 항목 | 설명 |
|------|------|
| 문서 유형 | 기획서, 요구사항, 설계서, 개발 기록, README |
| 저장·미리보기 | 시스템 내 에디터 + 렌더링 미리보기 |
| 검색 | 제목·태그·본문 전문 검색 |
| 버전 관리 | 수정 이력 보존 |

**원본 위치 원칙:**
- Git 저장소의 파일을 연결할지, 시스템에 직접 저장할지 프로젝트별로 결정
- 양쪽에서 수정할 때 **어느 쪽이 최신인지** 혼란이 생기지 않도록 **원본 위치를 명확히** 지정
- 권장: Git 저장소를 원본으로 하고, 시스템에서는 읽기·검색용 사본 유지

### 2.4 대시보드

대시보드는 전체 프로젝트 수보다 **실행에 필요한 정보를 우선** 표시한다.

| 위젯 | 표시 내용 |
|------|-----------|
| 진행 중 프로젝트 | 현재 활성 프로젝트 목록 + 상태 |
| 다음 할 일 | 프로젝트별 바로 착수할 작업 |
| 막힌 작업 | 블로커가 있는 작업 하이라이트 |
| 최근 변경 내용 | 최근 커밋·프롬프트·문서 변경 |
| 마감 임박 | 목표일 기준 D-7 이내 작업 |

## 3. 추가 기능

### 3.1 이슈·할 일 관리 `필수`

버그, 개선사항, 아이디어를 프로젝트별로 등록·추적한다.

| 필드 | 설명 |
|------|------|
| 제목 | 이슈 한 줄 요약 |
| 유형 | 버그 / 개선 / 아이디어 / 질문 |
| 상태 | 열림 → 진행 중 → 완료 / 보류 |
| 우선순위 | 긴급 / 높음 / 보통 / 낮음 |
| 담당 | 본인 / Devin / 기타 |
| 연결 작업 | 관련 작업·커밋·프롬프트 링크 |

### 3.2 개발 중단·재개 메모 `필수`

며칠 뒤에도 바로 작업을 재개할 수 있도록 **컨텍스트 스냅샷**을 남긴다.

```
── 중단 메모 ──────────────────────
마지막 작업: 로그인 API JWT 토큰 검증 구현
막힌 부분: refresh token 로테이션 로직 미완성
다음 작업: token rotation → 로그아웃 API → 프론트 연동
열어둘 파일: src/auth/token.ts, tests/auth.test.ts
참고 자료: https://...
기록일: 2026-09-20
────────────────────────────────
```

### 3.3 환경 설정 안내 `필수`

| 항목 | 설명 |
|------|------|
| 런타임 버전 | Node 20.x, Python 3.12 등 |
| 설치 명령어 | `npm install`, `pip install -r requirements.txt` |
| 환경변수 | 변수 이름과 **보관 위치** (`.env.example` 참조) |
| DB 연결 | 연결 문자열 위치, 스키마 파일 경로 |

> ⚠️ **API 키·비밀번호는 직접 저장하지 않는다.**
> 환경변수 이름과 보관 위치(예: `.env`, AWS Secrets Manager)만 기록한다.

### 3.4 통합 검색·태그 `필수`

- 프로젝트·프롬프트·문서·이슈를 **한 번에 검색**

- 필터: 프로젝트별, 상태별, 기간별

## 5. 데이터 모델

```
Project ─┬─ Task ──── PromptLog
         │            └─ Commit
         ├─ Issue
         ├─ Document (MD)
         ├─ PauseResumeMemo
         ├─ EnvironmentConfig
         ├─ GitInfo
         ├─ DeployInfo
         └─ TestRecord
```

### 주요 엔티티

| 엔티티 | 주요 필드 |
|--------|----------|
| **Project** | id, name, purpose, status, priority, start_date, target_date, tags |
| **Task** | id, project_id, title, status, assignee, created_at, updated_at |
| **PromptLog** | id, task_id, tool, prompt_text, result_summary, commit_hash, timestamp |
| **Issue** | id, project_id, title, type, status, priority, linked_task_id |
| **Document** | id, project_id, title, doc_type, content, source_location, version |
| **PauseResumeMemo** | id, project_id, last_work, blocker, next_work, open_files, recorded_at |
| **EnvironmentConfig** | id, project_id, runtime, install_cmd, env_vars_location, db_config_path |
| **GitInfo** | id, project_id, repo_url, branch, last_commit, last_pushed_at |
| **DeployInfo** | id, project_id, service_url, infra, version, deployed_at, deploy_method |
| **TestRecord** | id, project_id, target, method, result, unresolved_issues |

## 6. 설계 원칙

1. **작업 중심 기록** — 프롬프트·커밋·문서를 작업(Task)에 연결하여 개발 흐름을 추적
2. **즉시 재개 가능** — 중단 메모로 컨텍스트 전환 비용 최소화
3. **보안 우선** — 비밀 정보는 환경변수 이름·위치만 기록, 실제 값은 별도 관리
4. **원본 단일화** — 문서 원본 위치를 명확히 하여 동기화 충돌 방지
5. **점진적 확장** — MVP로 시작, 필요에 따라 기능 추가
